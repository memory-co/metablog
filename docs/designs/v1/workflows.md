# 使用流程

一条元认知从记下到发出去的路径。命令是**示意**，正式的命令手册等接口定下来再写。

## 1. 记素材（origin）

事情发生时，先把原始材料原样放进来，不加工：

```bash
metablog origin add '写代码/2026-09-28 和 Claude 的调试对话.md' --file ./chat.md
```

素材可以先放着不写。素材多、博文少很正常。

## 2. 写博文（post）

隔一会儿、情绪过去之后，针对一件事写一篇：

```bash
metablog post new 写代码/一次三小时的方向性错误 --kind 复盘 \
    --source '写代码/2026-09-28 和 Claude 的调试对话.md'
```

新建时套用模板的四段：**发生了什么 / 我当时怎么想的 / 现在怎么看 / 下次怎么做**。模板不强制，觉察、方法类的文章可以不按这四段写。写完以后正文还可以改。

## 3. 回看，写后记（afterword）

过一段时间（几周、几个月）回看旧文，有新看法就追加后记：

```bash
metablog post afterword 学习/我为什么总是高估自己读懂了
```

回看靠什么触发是个开放问题（见 [open-questions.md](open-questions.md)）。v1 的最低要求：能按「最近一次回看是多久以前」列出博文。

## 4. 提炼条目（insight）

发现几篇博文说的是同一件事时，写一条 insight，记下出自哪几篇：

```bash
metablog insight write 学习/流畅感不等于理解 \
    --post 学习/我为什么总是高估自己读懂了 --post 写代码/一次三小时的方向性错误
```

条目页反查列出「出自哪些博文」，从条目可以跳回具体情境。

## 5. 发布

选几篇公开，导出静态站：

```bash
metablog publish
```

发什么、不发什么见 [publish.md](publish.md)。

## 读

除了写，日常还要能这样读：

| 视角 | 看什么 |
|---|---|
| 时间线 | 博文按 `date` 倒序，后记按日期插进来 |
| 系列 | 按目录 |
| 标签 / kind | 横向聚合 |
| 条目 | 条目列表；每条带出处博文 |
| 素材 | 某篇博文基于哪些素材；某份素材被哪些博文用过 |
| 检索 | 全文（`git grep`） |
