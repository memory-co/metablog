# 内容模型

字段和目录形态的定义见 [structure/v1/metas.md](../../structure/v1/metas.md)。这里只讲为什么。

## 三层

| 层 | 是什么 | 一句话理由 |
|---|---|---|
| `origin` | 素材：对话记录、读书摘录、随手笔记，原样保存 | 反思要有出处；原样保存才能回头对照「当时到底发生了什么」 |
| `post` | 博文：一篇元认知 | 主形态，见 [product.md](product.md#为什么是博客) |
| `insight` | 条目：从几篇博文里提炼出的、反复成立的一条认识 | 博文是按时间的，条目是按道理的；两种索引都需要 |

三层从下到上依次抽象：素材是发生了什么，博文是我怎么看它，条目是我从多次经历里学到了什么。上层引用下层，下层不知道上层（博文记素材，条目记博文，反过来不记）。这样写下层时不用回头改上层，悬挂引用读时容忍即可。

## 为什么 post 是主形态

大多数元认知只在一篇博文里出现一次，没必要再抽成条目。如果强迫每条都抽成条目，就退化成了卡片笔记，丢掉了「当时的具体情境」，而情境恰恰是元认知最有用的部分。所以：

- **默认只写博文**。
- 一个想法在**两篇以上**博文里都出现了，才值得写一条 insight，并在 `posts` 里记下出自哪几篇。

## 博文为什么没有 title / series / status

- 标题就是目录名（`<标题>.post/`），改标题就是改目录名，git 能追到。
- 系列就是所在目录（`学习/`、`写代码/`），目录树即分类。
- 没有 `status`：删就是删，历史在 git。草稿怎么表达见 [open-questions.md](open-questions.md)。

## 后记为什么只增

回看时的新看法写在 `afterwords/<日期>.md`，**只增不改不删**，正文却可以随便改。理由：

- 正文是「当前最好的表述」，改错别字、补论证都正常，修订史在 git log 里。
- 后记是「某一天的我怎么看」，它的价值就在于是那一天写的。改了它就抹掉了看法变化的证据。
- 单独成文件，时间线和 git log 里都能一眼看到「这篇在什么时候被回看过」。

## 条目为什么可改可删

条目是对多篇博文的总结，随着证据增加应该变得更准，所以像维基词条一样直接改；改了哪里 git 记着。被推翻的条目可以删掉，推翻的过程本身值得写一篇博文。

## 用户层

三层是内置的。用户可以在 `~/.metablog/layers/` 加自己的层（例如「读书笔记」「周复盘」），格式和内置层一样，机制见 [storage.md](storage.md#层协议)。
