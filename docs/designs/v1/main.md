# metablog 设计（v1）

## 定位

metablog **把用户散落在各处的数据整合到一起，变成用户自己的博客，再输出出去**。

用户每天都在产生数据：和 AI 的对话、和人的聊天、录音、拍下来的纸面材料。这些东西分散在不同的应用里、格式各不相同，事后很难再用上。metablog 先把它们收进同一个地方，然后让它们变成博文，成为用户能读、能回看、能发出去的东西。

**资料库里是用户接触过的所有内容**：聊过的人、问过的 AI、听过的话、读过看过的东西。合在一起，它反映的是**用户和外部世界的关联**。博客则是用户站在这些关联之上的输出。

## 底层：资料库 + 博客

```
AI 会话 ─┐
普通对话 ─┤                ┌──────────┐            ┌──────────┐
音频录音 ─┼──── 收进来 ───▶ │  资料库  │ ── 写成 ──▶ │   博客   │ ── 输出 ──▶ 站点 / RSS / …
图片扫描 ─┘                └──────────┘            └──────────┘
                           原样保存、整理成文字         博文引用资料
```

| 部分 | 负责什么 | 不负责什么 |
|---|---|---|
| **资料库** | 把各种来源的数据收进来，原样保存，整理成统一的、可检索的文字 | 不决定写什么、不对外 |
| **博客** | 用户基于资料写出博文；博文引用它用到的资料；管理发布 | 不保存原始数据 |

资料库是输入，博客是输出。两者分开，资料库可以一直积累，博客按需从里面取。

## 资料库

### 资料库是什么

资料库不是文件仓库，而是一张「我和外部世界」的关联图。每份资料都是一次接触：在某个时间，通过某种方式，和某个人、某个 AI 或者某份材料发生了联系。所以除了内容本身，**和谁、通过什么、在什么时候**这几件事和内容一样重要。

### 先收这四类

| 类型 | 例子 | 原件格式 | 怎么变成文字 | 要记的元数据 |
|---|---|---|---|---|
| **AI 会话** | 和 Claude、ChatGPT 等的对话 | 平台导出的 JSON / Markdown | 本来就是文字，按轮次统一成「谁说的 + 说了什么」 | 平台、模型、开始时间 |
| **普通对话** | 微信、短信等和人的聊天记录 | 导出文件、截图 | 统一成「说话人 + 时间 + 内容」；截图走 OCR | 对话对象、时间范围 |
| **音频录音** | 会议、访谈、语音备忘 | m4a / mp3 / wav | 语音转写成带时间戳的文字，尽量分出说话人 | 录制时间、时长、说话人 |
| **图片扫描** | 纸质笔记、书页、白板、票据 | jpg / png / pdf | OCR 识别成文字 | 拍摄时间、内容来源 |

### 建议的几条原则（待你确认）

1. **原件原样保留，只读**。转写、OCR 得到的文字是派生物，单独存放，可以重新生成（比如以后换了更好的转写模型）。
2. **每份资料都是同一种「资料条目」**：原件 + 文字版 + 元数据（类型、时间、来源、涉及的对象）。四类资料只是来源不同，进库以后长得一样，检索和引用也就只需要一套。
3. **两条主轴：时间和关联对象**。每份资料都有一个发生时间，也都连着至少一个外部对象（一个人、一个 AI、一本书、一场会）。资料库既能按时间浏览，也能按对象看「我和这个人 / 这个 AI / 这本书之间都有过什么」。
4. **关联对象要能认出是同一个**。同一个人可能在微信聊天里、录音里、照片里都出现，需要能归到一起。v1 先让用户手动标注，自动识别以后再说。
5. **资料库全部私密**。里面有别人说的话、别人的声音，任何资料都不会被直接发布。

## 博客

- 一篇博文基于若干份资料写成，记下它**引用了哪些资料**，从博文可以回到原始的对话、录音或图片。
- 博文默认不公开，**逐篇选择**发布。发布时只发博文本身，不带出它引用的资料原件。
- 输出形态先做静态站 + RSS。

## 和之前三层设计的关系

之前的骨架按 origin（素材）/ post（博文）/ insight（条目）三层设计。对应到新的定位：origin 就是资料库，post 就是博客，insight 暂时不在这个定位里。`docs/structure/v1/` 和代码骨架还是三层模型，等这份定位定下来再对齐。

## 还没定的事

1. **博客写什么**：之前的设定是「以博客形态存元认知」。新定位下，博客的主题还限定在元认知吗，还是任何从资料里来的内容都可以？
2. **博文谁来写**：用户自己写、AI 从资料起草后用户改，还是两者都支持？
3. **资料怎么进来**：手动导入文件，还是对接各个平台自动同步？建议 v1 先做手动导入。
4. **转写和 OCR 在哪做**：本地跑模型，还是调用云端服务？
5. **关联对象有哪些种类**：先定人、AI、材料（书、文章、网页）三种，够不够？
